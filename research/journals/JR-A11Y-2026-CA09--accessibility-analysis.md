# Accessibility and Inclusive Communication Analysis

## Model and evidence

Accessibility spans perceivability, operability, understandability, robust
semantics, and cognitive adaptation. W3C cognitive guidance treats clear
language and structure as only part of the need [EV-A11Y-2026-58E0].
Human-centred lifecycle design already requires user-context consideration
[EV-BOUNDARY-2026-274A], and expertise changes guidance effects
[EV-COG-2026-27F1].

## Counterevidence and methods

Plain language can remove necessary technical precision. “Average user” testing
excludes important variability. Automated accessibility checks miss cognitive
and contextual barriers. Methods include assistive-technology tests, keyboard
operation, cognitive walkthroughs, comprehension/action studies, multilingual
tests, and participatory research.

## Coverage, gap, and challenged assumptions

Accessibility/HCI already owns inclusive delivery. It rejects universal templates
and the idea that readability scores establish accessibility. Repository evidence
lacks direct disabled-developer participation.

## Discriminating experiment

Participatory evaluation across assistive technology, expertise, language, and
cognitive profiles; compare adaptive versus fixed handoffs.

## Confidence and limits

High standards-based overlap; Low empirical evidence specific to handoffs.
